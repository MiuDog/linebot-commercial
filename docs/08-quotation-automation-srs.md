# LINE AI 自動化報價系統軟體需求規格

狀態：使用者已核准  
版本：1.0  
時區：Asia/Taipei  
適用專案：linebot-commercial

## 1. 目標

本功能讓公司人員透過 LINE 官方帳號的一對一對話提供客戶資料、品項、數量及工程圖片。AI 與 OCR
負責將非結構化訊息轉成固定資料、判斷缺漏並選擇下一個補充動作；程式碼負責主檔解析、金額運算、
報價編號、Excel／PDF 產出、檔案保存、資料庫紀錄與 LINE 回覆。

成功條件如下：

- 使用者不必自行編輯 Excel，即可完成 CNS、一般架、船用、空白及銷售五種報價。
- 任何 AI／OCR 結果在建立正式報價前都可由使用者預覽、補充、修正或取消。
- AI 不得自行決定固定品項資料、計算金額、稅額或最後價格。
- Excel、PDF、圖片資產及資料庫紀錄可互相追溯。
- 原始 Excel 的圖片、蓋章、正定信箱、正定電話與底部重要資訊不得被覆蓋或改寫。

## 2. 已確認假設

1. 系統沿用 Java 25、Spring Boot 4.1、SQLite 與現有 LINE webhook 架構。
2. 正式執行環境為 Windows，且已安裝可由背景程序操作的 Microsoft Excel。
3. 日期、每日流水號及有效期限皆以 Asia/Taipei 日曆日計算。
4. 五種報價現階段固定外加 5% 稅額，不支援免稅或含稅價反推。
5. LINE Messaging API 無法由機器人直接傳送 PDF，因此改傳報價摘要與 PDF 安全下載連結。
6. LINE 可接收使用者上傳的圖片，也可用公開 HTTPS 原圖及縮圖網址回傳圖片預覽；網址使用不可猜測權杖。
7. 第一階段只處理使用者直接提供的品項與數量；長寬高、體積及工程公式推算屬第二階段。

## 5. 使用者與互動範圍

### UI-01 一對一私訊

- 報價建立流程只允許 LINE `user` 來源。
- 群組或多人聊天室不得建立、修改或確認報價草稿。
- 群組收到報價指令時，只提示使用者改至一對一聊天室，不回傳客戶或價格資料。

### UI-02 名片與文字提取

- 使用者可輸入文字或上傳名片圖片。
- AI／OCR 可提取公司名稱、聯絡人、電話、傳真、信箱、工程地點及其他抬頭資料。
- 每個提取欄位保存來源訊息、信心分數及原始文字。
- 低信心或無法辨識欄位列為缺漏，不得猜測。
- 提取結果必須進入預覽，使用者確認後才寫入已確認草稿資料。

### UI-03 缺漏資訊補充

- 頂部基礎資訊缺漏時，一次列出全部缺少欄位。
- 多個品項不完整時，以單一清單列出每一品項缺少的欄位。
- 使用者可以一次補齊全部資料，也可以分多次回答。
- 每次新訊息都重新合併草稿、解析及驗證，只追問仍缺少的資料。
- AI 輸出 `nextAction`，應用程式再呼叫內部 LINE 發訊函式；AI 不直接持有 LINE 權杖。
- 補充訊息及預覽訊息都必須附上「取消報價」Quick Reply 或按鈕。

### UI-04 最終確認

- 產出前顯示公司、工作名稱、報價格式、客戶資料、完整品項、圖片、未稅、稅額及含稅總額。
- 動態品項與臨時品項需明確標示，避免誤認為正式主檔。
- 只有明確的確認 postback 能建立正式報價；一般文字中的「好」不得視為確認。
- 使用者可要求修改、替換圖片或取消。

## 6. 報價資料模型

### DB-01 固定品項主檔

固定品項至少包含：

- 穩定品項代碼
- 品項名稱及 AI 辨識別名
- 報價格式
- 規格／說明
- 單位
- 單價
- 備註
- 顯示順序
- 計價模式
- 客戶可見狀態與啟用狀態

數量與複價不屬於固定主檔，只能存在草稿及正式報價快照。

### DB-02 正式報價快照

正式報價必須保存建立當下的品項名稱、規格、單位、單價、數量、複價與備註。日後修改主檔不得改變
既有報價。

正式報價另保存：

- 報價日期、每日流水號及完整單號
- 公司名稱、工作名稱與客戶抬頭
- 未稅小計、5% 稅額及含稅總額
- Excel 與 PDF 的相對路徑、雜湊及產生狀態
- 選用圖片與全部候選圖片的資產關聯
- LINE 接收者、傳送狀態、嘗試次數、錯誤摘要及時間
- 確認者、確認訊息及確認時間

### DB-03 臨時與動態品項

- CNS／一般架每張報價最多 2 筆臨時品項。
- 臨時品項需有品項、規格、單位、單價、數量及備註並經使用者確認。
- 空白／一式及銷售報價可有動態品項，不受 2 筆限制，但受 Excel 分頁與合理輸入上限限制。
- 臨時及動態品項只保存於草稿與正式報價快照，不自動寫入固定品項主檔。

### DB-04 流水號一致性

- 每日流水號以資料庫交易分配，唯一鍵為「報價日期＋流水號」。
- 只有通過最終確認且即將建立 Excel 時才分配號碼。
- 取消或資料不足的草稿不得消耗流水號。
- 同時建立多張報價時不得取得相同號碼。
- 顯示寬度至少兩位；第 100 張起允許自然擴充為三位，避免碰撞。

## 7. 五種報價模組

### MOD-01 CNS 與一般架

- 兩者計算方式相同，固定主檔及單價版本不同。
- 預設列出該格式全部啟用中的品項。
- 使用者提及的品項填入數量，程式計算複價。
- 未提及品項保留規格、單位、單價及備註，數量與複價保持空白且不加入合計。
- 使用者可明確刪除固定品項。
- 允許最多 2 筆經確認的臨時品項。

### MOD-02 船用

- 客戶版報價不顯示內部詳細計算過程，只顯示最終彙總結果。
- 沿用五份 Excel 的 5% 稅額與含稅總額欄位。
- 建立前一定詢問使用者是否提供工程圖片。
- 沒有圖片時，只有使用者明確選擇「不提供圖片」才可繼續。

### MOD-03 空白／一式

- 支援 1 至多筆動態工程項目及直接輸入的一式價格。
- 不使用 CNS／一般架的固定鎖價清單。
- 建立前一定詢問使用者是否提供工程圖片。
- 沒有圖片時，只有使用者明確選擇「不提供圖片」才可繼續。

### MOD-04 銷售報價

- 報價單號顯示沿用範本的 `S` 前綴。
- 品項、規格、單位、單價、數量及備註可完全依使用者輸入動態建立。
- AI 只能提取使用者明確提供的單價，不得推測價格。
- 動態品項不回寫正式品項主檔。
- 完整預覽經明確確認後才能輸出。

## 8. AI 固定資料契約

AI JSON 契約升級至 2.x，至少分為以下區塊：

```json
{
  "schemaVersion": "2.0",
  "schemeCode": "CNS",
  "headerPatch": {},
  "standardItemIntents": [],
  "customItems": [],
  "removedItemCodes": [],
  "imageAssessments": [],
  "selectedImageMessageId": null,
  "imageDeclined": false,
  "missingBaseFields": [],
  "missingItemFields": [],
  "nextAction": "REQUEST_BASE_FIELDS",
  "warnings": []
}
```

契約限制：

- `schemeCode` 由使用者指定，AI 不得判定：應用程式以固定關鍵字解析使用者原文（CNS／一般架／船用／空白／銷售），
  解析不到時以 LINE 按鈕請使用者選擇，選定後即鎖定，同一張報價不再變更。
- 驗證層以應用程式鎖定的格式為準：AI 未指定格式時宣稱任何格式都會被拒絕，已指定時提出不同格式也會被拒絕。
- `MARINE`、`BLANK`、`SALES` 不使用固定品項目錄：這三種格式的 `standardItemIntents` 與 `removedItemCodes` 必須為空，
  全部品項改以 `DYNAMIC` 由使用者說明名稱、規格、單位、單價與數量。
- `headerPatch` 只包含本次訊息明確提供或 OCR 提取且信心至少 `0.75` 的資料；每個欄位保存值、來源原文及信心。
- 頂部欄位白名單為公司名稱、工作名稱、聯絡人、電話、傳真、信箱、工程地點及其他抬頭資料。
- 標準品項只允許輸出 `itemCode`、`matchedName`、數量、來源文字與信心。
- 標準品項的名稱、規格、單位、單價及備註由資料庫補齊。
- 送給模型的 JSON Schema 會依當下啟用目錄動態綁定 `itemCode` 列舉；目錄為空時標準品項與刪除品項的 `maxItems` 皆為 `0`。
- 後端另行拒絕 `UNKNOWN`、`NA`、`OTHER`、`TBD` 等佔位代碼，並要求改以 `missingItemFields` 回問。
- 使用者說法與主檔名稱不同但信心至少 `0.75` 時，模型照常對應目錄代碼並把使用者原本說法填入 `matchedName`；該原文會保存在 `quotation_draft_item.matched_name`，並在完整預覽的「名稱對應」段落請使用者於確認前核對。
- 信心低於 `0.75` 或可能對應到兩個以上品項時，不得輸出該筆標準品項，改列入 `missingItemFields`（`fields` 含 `itemCode`）。
- 動態或臨時品項可提取使用者明確提供的固定欄位，但不得捏造缺漏值。
- AI 不得輸出複價、小計、稅額、含稅總額、流水號、檔案路徑或傳送狀態。
- `missingBaseFields` 一次列出全部頂部缺漏；`missingItemFields` 每個品項只使用一個分組列出全部缺漏欄位。
- `nextAction` 只允許 `REQUEST_BASE_FIELDS`、`REQUEST_ITEM_FIELDS`、`REQUEST_IMAGE_DECISION`、`SHOW_PREVIEW`；它只是宣告，只有應用程式能執行下一步。
- 每張候選圖片保存品質、視角、區別度及理由；選圖必須為最高區別度之一，同分可任選。
- 驗證成功資料會補齊標準品項的資料庫固定欄位，供完整預覽使用；計算結果仍由後續確定性計價服務建立。
- 後端必須拒絕未定義欄位、無效狀態轉換、超過兩筆的 CNS／一般架臨時品項及非最高分選圖。

## 9. 計算規則

所有計算使用 `BigDecimal` 或等價精確十進位型別：

```text
複價 = 數量 × 單價
未稅小計 = 所有具數量且未刪除品項的複價總和
稅額 = 未稅小計 × 0.05
含稅總額 = 未稅小計 + 稅額
```

- 數量空白的鎖價列不等於 0，且不加入未稅小計。
- AI 不參與任何數學運算。
- 第一階段不從空間尺寸推算數量。
- 金額以最多兩位小數保存與顯示；計算過程不使用二進位浮點數。

## 10. 日期、單號與檔名

- 報價日期預設為確認當日。
- 有效期限為報價日期加 15 個日曆天。
- 內部基礎單號格式為 `YYYYMMDDXX`，例如 `2026081101`。
- 銷售報價在 Excel 顯示時加上範本既有的 `S` 前綴。
- 公司名稱與工作名稱為必要欄位，缺少時不得產出。
- Excel 及 PDF 基本檔名為 `公司名稱-工作名稱 YYYYMMDD-XX`。
- Windows 不合法字元、尾端空白及尾端句點需安全移除；檔名清理不得改變 Excel 內的正式名稱。

## 11. 檔案與資料庫儲存

### FILE-01 路徑

```text
QUOTATION_ROOT_PATH=<使用者指定的上層根目錄>

<使用者指定根目錄>/
└─ 報價單/
   └─ YYYYMMDD-XX/
      ├─ 公司名稱-工作名稱 YYYYMMDD-XX.xlsx
      ├─ 公司名稱-工作名稱 YYYYMMDD-XX.pdf
      ├─ YYYYMMDD-XX-01.jpg
      └─ YYYYMMDD-XX-02.jpg
```

- `QUOTATION_ROOT_PATH` 留空時可相容使用 `QUOTATION_OUTPUT_PATH`；兩者都留空時禁止正式產出。
- 兩個變數都代表 `報價單/` 的上層；例如目標是 `E:/報價單` 時應填 `E:/`。
- 系統自動建立且只寫入根目錄下的固定 `報價單` 子資料夾。
- 使用者正式確認並取得流水號後，才建立 `報價單/YYYYMMDD-XX/` 資料夾。
- Excel、PDF 與該報價的全部候選原圖存放在同一個日期流水號資料夾。
- 公司名稱及工作名稱只用於產出檔名，不用於資料夾名稱。
- 取消或尚未確認的草稿不得建立正式報價資料夾。
- 資料庫保存相對於報價根目錄的路徑，以支援整包搬移。
- 檔案與資料庫需有補償機制，避免只建立檔案或只建立紀錄的半完成狀態。

### FILE-02 PDF

- Excel 建立成功後，由背景 Microsoft Excel 依原始列印設定匯出 PDF。
- 應用程式只能呼叫專案內固定的 `scripts/export-quotation-pdf.ps1`，並以獨立參數傳入 XLSX 與 PDF 絕對路徑；禁止串接或執行來自指令的 PowerShell 內容。
- PDF 必須與原 XLSX 位於同一資料夾且使用同一基本檔名；路徑不得離開 `<QUOTATION_ROOT_PATH>/報價單/`。
- 匯出預設逾時為 90 秒，可以 `QUOTATION_PDF_TIMEOUT_SECONDS` 調整；逾時時必須終止 PowerShell 及其 Excel 子行程。
- PDF 成功後才可進入 LINE 可交付狀態。
- 未安裝 Excel、系統無可用印表機、COM 啟動失敗、逾時或匯出錯誤時，清除同名不完整 PDF、保留原 Excel 並標記 `PDF_FAILED`。
- 管理頁顯示不含本機絕對路徑的失敗原因並提供重試；重試必須沿用原報價識別碼、流水號、XLSX 與 PDF 路徑，不得重新分配或覆寫不同報價。

### FILE-03 圖片資產整合

- LINE 收到的每一張候選原圖在草稿期間先保存在 `.pending`，不得提前建立正式報價資料夾。
- 正式確認並取得報價流水號後，將全部候選原圖移入 `報價單/YYYYMMDD-XX/`。
- 每張圖片只保留一份正式實體檔案；搬移完成後更新圖片資產資料庫的相對路徑、檔案識別與報價關聯。
- 只有 AI 選中的一張圖片嵌入 Excel；未選中的候選圖仍保存在同一報價資料夾並可由資產資料庫追溯。
- 取消草稿時不建立報價資料夾，候選圖片依既有待確認圖片資產規則處理。
- 檔案搬移與資料庫更新需有補償流程；失敗時不得留下兩份正式原圖或指向不存在檔案的資產紀錄。

## 12. 圖片選擇與版面

- 船用與空白格式一定執行圖片詢問；CNS、一般架及銷售在使用者有提供圖片時可選圖。
- 最多一張圖片進入報價單。
- 多張候選圖由 AI 評估清晰度、品質、視角與內容區別度，選出最高分圖片。
- 後端驗證選中的圖片確實存在於草稿候選集合，且分數不得低於其他候選圖。
- 最終確認畫面顯示選圖，允許更換、移除；船用／空白移除後需再次選圖或明確拒絕。
- 圖片放在全部品項之下，以保持比例的 `CONTAIN` 方式縮放。
- 圖片不得覆蓋小計、稅額、總價、付款說明、正定信箱、正定電話或蓋章。
- 當頁空間不足時，圖片移至新頁；不得為塞入圖片而壓縮到無法辨識。

## 13. 分頁與 Excel 保護

目前五份範本萃取出的單頁明細容量如下：

| 格式 | 工作表 | 單頁現有明細容量 | 稅率 | 顯示規則 |
| --- | --- | ---: | ---: | --- |
| CNS | CNS | 21 | 5% | 全部鎖價品項 |
| 一般架 | 一般架 | 20 | 5% | 全部鎖價品項 |
| 船用 | 船用 | 13 | 5% | 只顯示最終結果 |
| 空白 | 空白 | 18 | 5% | 動態項目 |
| 銷售 | 銷售報價單 | 18 | 5% | 動態項目、單號加 S |

- 分頁判斷以實際範本明細列與底部區塊為準，不硬編碼「30 項」。
- 超過單頁容量時複製可重複的頁面區塊，延續表頭、頁碼及必要識別資訊。
- 明細列不得與合計區塊分離成無法理解的版面。
- 只有最後一頁顯示合計與完整底部資訊，或依範本驗收後採等價且不重複計價的配置。
- 程式可改寫的儲存格必須白名單化；原始圖片、蓋章、正定信箱及正定電話位於禁止改寫區。

## 14. LINE 對話狀態機

建議狀態如下：

```text
COLLECTING_BASE_INFO
COLLECTING_ITEMS
AWAITING_IMAGE
READY_FOR_PREVIEW
AWAITING_CONFIRMATION
CONFIRMED
CANCELLED
EXPIRED
```

- 每個 webhook 事件以 LINE message ID 做冪等處理。
- `CANCELLED`、`EXPIRED` 與 `CONFIRMED` 為草稿終態；舊 postback 不得使終態草稿復活。
- 同一使用者同時間只允許一張進行中的報價；新建前需完成或取消舊草稿。
- 取消按鈕需帶不可猜測且綁定草稿與使用者的 postback 資料。
- 程式根據驗證結果決定下一狀態，不接受 AI 直接指定任意狀態。

## 15. LINE 交付

LINE 官方不支援機器人直接傳送 PDF，因此交付方式為：

1. 系統保存 PDF 並建立不可猜測的下載權杖。
2. LINE 傳送 Flex Message，顯示公司、工作名稱、單號、未稅、稅額及含稅總額。
3. Flex Message 提供「下載 PDF」HTTPS 按鈕。
4. 下載端點驗證權杖、有效期限及檔案狀態，並以 `application/pdf` 回傳。
5. 管理頁可撤銷連結、重建連結及重試 LINE 傳送。

選圖預覽使用 LINE image message：原圖與縮圖皆由 HTTPS 安全網址提供，並分別使用適合的內容尺寸；
預覽權杖不得暴露本機檔案相對路徑。

下載連結預設有效期限為 7 天（168 小時）；可由環境變數調整，但單次不得超過系統安全上限。

## 16. 本機管理頁

管理頁除現有主檔功能外，需提供：

- 報價草稿與正式報價列表、搜尋及狀態篩選。
- 完整預覽、品項快照、選圖、未稅、稅額及含稅總額。
- Excel／PDF 本機下載。
- `PDF_FAILED` 原因及重試按鈕。
- LINE 傳送狀態及重試按鈕。
- 安全下載連結的建立、撤銷及到期時間。
- 稽核紀錄，不顯示 AI 金鑰、LINE 權杖或原始敏感日誌。

實作邊界：草稿選圖與正式選圖由僅限 loopback 的同源管理圖片端點提供；端點必須以資料庫關聯確認
草稿來源擁有者或正式報價關聯，並以正規化、實體路徑及符號連結檢查限制在 `.pending` 或
`報價單` 根目錄。重建 PDF 連結只回傳可複製的短效 HTTPS URL 與到期時間，不另回傳 raw token，
且稽核摘要不得記錄 URL 或權杖。

## 17. 程式碼風格

- Java、JavaScript、HTML、CSS、SQL 與 Markdown 依個人程式風格規則。
- 預設使用 Tab；YAML 等語法禁止 Tab 時除外。
- 每個 Java 方法上方使用中文方法註解。
- 外部 API、資料庫、檔案系統、COM 與序列化呼叫前加入中文目的註解。
- 輸入先驗證，直接 guard 保持精簡，金額一律使用 `BigDecimal`。

```java
// 方法：確認草稿完整後分配每日報價流水號。
public QuotationNumber confirm(long draftId, LocalDate quotationDate) {
	QuotationDraft draft = repository.findDraft(draftId).orElseThrow();
	if (!draft.isReady()) throw new QuotationException("報價資料尚未完整");

	// 資料庫：在單一交易內分配日期流水號並建立正式報價快照。
	return repository.confirmAndAllocateNumber(draft, quotationDate);
}
```

## 18. 測試策略

### 18.1 單元測試

- 缺漏欄位合併與下一動作決策。
- CNS／一般架全品項展開、空白數量及明確刪除。
- 臨時品項上限與動態品項驗證。
- 精確複價、5% 稅額及含稅總額。
- 日期、15 天期限、每日流水號與安全檔名。
- 圖片最高分選擇及船用／空白拒絕圖片流程。
- 狀態機合法／非法轉換與取消冪等性。

### 18.2 整合測試

- SQLite 並行流水號唯一性與正式快照不受主檔修改影響。
- LINE webhook 多輪補充、確認、取消及重送事件。
- Excel 建立、PDF 成功／失敗及重試。
- PDF 權杖到期、撤銷、錯誤檔案與路徑穿越防護。
- 管理 API 與本機存取限制。

### 18.3 實際驗證

- 五種 Excel 使用試算表工具檢查公式錯誤、內容與渲染版面。
- 五種 Excel 及 PDF 使用本機 Microsoft Excel 開啟並比對頁數、圖片、蓋章與固定聯絡資訊。
- 管理頁以真實瀏覽器檢查桌面／窄螢幕、鍵盤操作及零 console error。
- LINE 沙盒實測一對一補充、取消、圖片、確認與 PDF 下載連結。

## 19. 邊界

### 一律執行

- 驗證 LINE 簽章、來源類型、message ID 冪等性及 postback 所有權。
- 在使用者確認前保留為草稿，不分配號碼、不產出正式檔案。
- 所有金額由程式計算並保存正式快照。
- 使用相對路徑與不可猜測下載權杖。
- 每個新行為先建立失敗測試，再實作並執行完整測試。

### 需先詢問

- 更改 5% 稅率、單號格式或銷售 S 前綴。
- 更改五份 Excel 的固定圖片、蓋章、正定信箱、正定電話或列印區。
- 引入新的外部 OCR、檔案代管或雲端資料庫服務。
- 實作第二階段工程公式。

### 絕不執行

- 讓 AI 決定標準品項單價、複價、稅額、總價或流水號。
- 未確認即產出、傳送或覆寫正式報價。
- 將 AI、LINE 或下載權杖寫入日誌、Excel 或公開網址。
- 自動把銷售或臨時品項加入正式主檔。
- 以圖片覆蓋底部重要資訊或變更原始固定圖章與聯絡方式。

## 21. 明確延後項目

- 依長、寬、高、周長、體積或工程公式自動推算品項與數量。
- 個別案件免稅、含稅價反推或非 5% 稅率。
- 將臨時品項一鍵升級為正式主檔。
- 群組內直接建立或修改報價。

## 22. 已核准第一階段商業規則

1. PDF 安全下載連結預設有效 7 天（168 小時）。
2. 品項複價、小計、稅額及總價統一保存至小數點後兩位，使用 `HALF_UP` 四捨五入。
3. 空白及銷售格式的動態品項每張最多 200 筆；AI 契約、驗證、對話狀態及計價入口均採相同上限。CNS／一般架的臨時品項仍維持最多 2 筆。

## 23. 2026-08-11 已核准補充規則

- `salesRepresentative`（業務承辦）為每張報價由使用者輸入的必要抬頭欄位；低信心時不可猜測，需與其他缺漏抬頭一次詢問，確認後保存於正式不可變快照並寫入五種範本的 `G6`。
- 資料庫必須保證同一 LINE 私訊使用者同時只有一份進行中草稿；遷移時保留全部歷史資料，較舊的重複進行中草稿轉為 `CANCELLED`。
- 圖片改選、移除及候選翻頁 postback 必須以 HMAC 綁定 owner、draft、revision、expiry 及候選圖片／頁碼。
- LINE 同次回覆僅最後一則訊息的 Quick Reply 會顯示，因此完整預覽只允許最後一則 confirmation Flex 攜帶第一頁圖片操作；超過一頁時以簽章 `IMAGE_OPTIONS_PAGE` postback 取得單一、可前後翻頁的選項訊息，每頁不得超過 13 個 Quick Reply。
- 「移除目前圖片」只取消 Excel 嵌入選取，不刪除候選圖片關聯或原圖。船用／空白格式需重新詢問上傳或明確拒絕；拒絕後 selected 為空，但全部候選仍於正式確認時歸檔。
